# Architecture checkpoint

The app is TypeScript/React/Vite with a Three.js viewport. It runs under `/notCAD/` and uses only hash/local state for navigation. All model operations run in a dedicated module worker. Kernel and solver assets are bundled, single threaded, and do not need cross-origin isolation. The current kernel WASM is about 23 MB before transport compression. There are no third-party fonts or runtime network services.

`src/model/document.ts` defines a strict version-1 document schema. Sketches carry a plane, offset and a rectangle/circle profile; downstream features reference stable sketch/part-producing feature IDs. `graph.ts` validates backwards dependencies, determines affected descendants, and blocks invalid reorders/deletions. Face/edge persistent naming, incremental regeneration and general sketch entities remain future work. Faces returned for display have temporary tessellation indexes only; no feature references those indexes.

`src/kernel/engine.ts` directly calls the OpenCascade.js bindings from the LGPL custom `replicad-opencascadejs` single-threaded build. It does not use the Replicad modeling library. Every bound object has a scope that calls `delete()`, including failure paths. No exact shape pointers cross the worker boundary. Each regeneration currently rebuilds the whole history, validates solids and returns tessellation plus exact volume/area. A part must remain one connected solid; disconnected boolean results fail explicitly until split-part identity is implemented. Fillet/chamfer currently process all edges rather than a persistent selection. PlaneGCS receives typed profiles and reports solving status, freedom and conflicting/redundant IDs. A separate assembly solver is still required.

`protocol.ts` carries request IDs and revisions. `client.ts` resolves each ID once, times out requests, and replaces the worker on cancel/crash. The UI hydrates recovery data before geometry loading and keeps it downloadable even after startup cancellation. It commits a candidate document only after successful regeneration, with revision and request sequence checks. The worker client also fences every response by expected revision/type and rejects requests after disposal. Cancellation and failures leave the committed document and rendering intact. New requests contain the full committed/candidate document so a restarted worker can reconstruct its state. History stores validated copies of input documents; revisions remain monotonic through undo/redo. Feature edits restore the end of the history; rollback remains an explicit document field.

`src/storage/project.ts` writes a ZIP with `manifest.json` and `document.json`. It rejects unsupported versions, unknown entries, duplicate entries, malformed references, excessive feature counts, invalid numbers and oversized compressed/decompressed inputs before accepting a document. Version 1 has no assets/caches because supported features do not need them. No previous format exists to migrate; future format revisions must retain supported migrations and must not overwrite input files. The UI validates and regenerates an opened project before replacement, and keeps its previous project available through undo.

IndexedDB uses one read/write transaction to rotate `latest` and `previous` snapshots. Saves are serialized by the UI. Quota and interrupted-write tests verify that the old transaction remains committed. Visible storage failure messages retain an explicit project download route. Snapshots are a bounded two-version recovery mechanism, not the named local-version library required by parity.

Geometry verification uses analytic fixtures. Scale-aware scalar comparison tolerance is `max(1e-7, |expected| * 1e-8)` in the quantity's units (mm, mm², mm³). Fixture scales cover 0.001–1000 mm; this does not establish all extreme geometries. Rendering uses 0.1 mm linear and 0.3 rad angular deflection and is not used for exact measurement. STEP currently has a kernel self-roundtrip; independent STEP/IGES reading remains unverified. STL ASCII triangle volume is checked independently of kernel mass computation.

CI builds once, retains the artifact, and browser jobs test that artifact under `/notCAD/`. It deploys that artifact as an unfinished public preview after all four browser projects pass, as explicitly authorized by the user. A dedicated live smoke job checks the deployed entry asset, WASM loading, modeling, persistence and exports. `gate:release` deliberately fails until the complete documentation audit, parity tests, independent exchange readers, physical devices, release artifact digest and data-loss checks have evidence. The final release pipeline, rollback archive and deployed smoke tests must be implemented only when those prerequisites are met.
