## Test and repair cycle for every slice

1. Establish the current passing baseline and preserve fixtures/evidence. For defects, add a regression that demonstrates the failure before changing behavior.
2. Implement the smallest complete workflow. Run focused geometry, solver, history or storage tests according to the change. Check invalid input and failure preservation alongside success.
3. Run `npm test` and `npm run build`. Serve that compiled artifact and run all browser projects with `npm run test:e2e`; use a managed display on Linux where Firefox needs it.
4. After the implementation appears finished, perform another adversarial validation round. Include scale and unit boundaries, early history edits, missing/ambiguous references, cancellation at different stages, worker restart, interrupted saves, malformed imports, drawer/keyboard behavior and repeated operations.
5. Fix every confirmed finding, add a meaningful regression, rebuild once, and rerun the complete automated suite on the repaired artifact. If another defect appears, repeat this cycle. Treat host failures separately and rerun invalidated tests; do not count them as successful verification.
6. Before publishing a preview, require the build and all implemented browser regressions. After deployment, run `npm run test:smoke` against the published URL using the downloaded tested artifact. Preserve reports, traces, screenshots, commit and digest. A failing live smoke check means the preview needs investigation or rollback; the current workflow reports failure but does not automatically roll back.

`npm run test:smoke` defaults to the public Pages URL. Set `NOTCAD_SMOKE_URL` to a staging/local URL ending in `/notCAD/` to check an unpublished candidate. It expects an existing `dist/` artifact and does not rebuild it. Smoke tests use their own directory/configuration and do not change the 52-case modeling regression baseline.

## Evidence and limits

Record each run's command, browser/version, test counts, skips/flakes, artifact digest and result. Never substitute emulator results for physical devices. Preserve the previous downloadable CI artifact for diagnosis; implement and test explicit rollback before declaring a full release.

For memory/performance work, first measure cold start, warmed regeneration and repeated feature edits on fixed fixtures. Record browser/WASM memory, outstanding native handles and timing distribution over at least 100 cycles. Compare the final warmed batches against earlier warmed batches; explain heap reservations separately from live allocations. Choose budgets from measured desktop and real phone baselines and record them before treating performance as accepted.

For new project versions, test old-format migration, unknown/future versions, missing assets, interrupted writes and reopening the original input unchanged. For exchange, use an independent reader and assert units, bounding dimensions, topology and exact quantities with documented tolerances; a kernel self-roundtrip alone is not acceptance.

Next modeling slice: inspect the solver bindings and document schema, then implement editable line-based sketch constraints with consistent, underconstrained, redundant, inconsistent and degenerate fixtures before extending downstream feature modes.
